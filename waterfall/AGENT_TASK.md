Это учебный курсовой проект по дисциплине о моделях жизненного цикла ПО. Работа ведётся **по модели Waterfall**: этапы идут строго по порядку, и после каждого этапа ты **останавливаешься и ждёшь моего подтверждения**, прежде чем переходить к следующему.

Этапы и точки остановки:

1. **Требования.** Перечитай разделы 1–4, задай вопросы, если что-то неясно или противоречиво. → *стоп*

5. **Отчёт.** Сформируй пояснительную записку по шаблону (раздел 8). → *стоп*

Внедрение и сопровождение **не выполняются**: их нужно только описать в отчёте (раздел 7). Ничего не деплоить, не создавать репозитории на GitHub, не настраивать CI.

## 1. Цель продукта

Одностраничный сайт (лендинг) вымышленного фитнес-клуба **PulseFit**. Посетитель знакомится с клубом, сам рассчитывает стоимость абонемента в калькуляторе и оставляет заявку.

## 2. Состав страницы

1. **Шапка (Header):** логотип-текст «PulseFit», якорное меню (О клубе, Тарифы, Калькулятор, Контакты), кнопка «Оставить заявку» (скролл к форме). На ширине < 768 px меню сворачивается в бургер.
2. **Hero:** заголовок, подзаголовок, кнопка «Рассчитать абонемент» (скролл к калькулятору).
3. **О клубе:** 4 карточки преимуществ (иконка + заголовок + 1–2 предложения). Иконки — inline SVG или emoji, без сторонних иконочных библиотек.
4. **Тарифы:** 3 карточки (Базовый, Стандарт, Премиум) с ценой за месяц и составом. Данные берутся из того же конфига, что и в калькуляторе.
5. **Калькулятор:** см. раздел 3.
6. **Форма заявки:** см. раздел 4.
7. **Футер (Contacts):** адрес, телефон, часы работы, ссылки на соцсети (заглушки `#`).

Изображения: без фотографий людей. Допускаются градиенты, абстрактные SVG-фигуры.

## 3. Калькулятор абонемента

### 3.1. Параметры

| Параметр | Значения |
|---|---|
| Тариф | Базовый 2 500 ₽/мес (тренажёрный зал); Стандарт 3 500 ₽/мес (зал + групповые занятия); Премиум 5 000 ₽/мес (всё + бассейн и сауна) |
| Срок | 1, 3, 6, 12 месяцев |
| Скидка за срок | 1 мес — 0 %, 3 мес — 5 %, 6 мес — 10 %, 12 мес — 15 % |
| Шкафчик | чекбокс, 500 ₽/мес, без скидки за срок |
| Полотенце | чекбокс, 300 ₽/мес, без скидки за срок |
| Персональные тренировки | целое число 0–20; 1 500 ₽/шт, при количестве ≥ 10 — 1 300 ₽/шт; без скидки за срок |
| Промокод | текстовое поле, необязательное; действующий промокод `12345` (моковый, хранится в `pricing.ts`) — скидка 3 % на итоговую сумму с учётом доп. услуг и тренировок |

### 3.2. Формула

```
скидка   = скидка_за_срок
тариф    = цена_тарифа × месяцы
сумма    = тариф × (1 − скидка)
         + (шкафчик + полотенце) × месяцы
         + тренировки × цена_тренировки
промокод = 3 %, если введён действующий промокод, иначе 0
итог     = round( сумма × (1 − промокод) )
в_месяц  = round(итог / месяцы)
```

Округление `Math.round` до целых рублей.

### 3.3. Отображение
Калькулятор пересчитывается сразу при изменении любого поля и показывает разбивку:
стоимость тарифа без скидки, скидка за срок (% и ₽), доп. услуги, тренировки, скидка по промокоду (% и ₽, только если промокод применён), **итого**, цена в месяц. Суммы форматируются с разделителем тысяч (`toLocaleString('ru-RU')`) и знаком ₽.

### 3.4. Валидация
Поле «Тренировки»: только целое число от 0 до 20. Пустое поле, дробь, отрицательное или большее 20 значение → поле подсвечивается красным, под ним текст ошибки, итог не пересчитывается (показывается последний корректный).

Поле «Промокод»: пробелы по краям игнорируются. Пустое поле — скидки нет, ошибки нет. Действующий промокод — под полем сообщение о применённой скидке. Непустой недействующий промокод — после потери фокуса поле подсвечивается красным, под ним текст «Промокод не найден»; скидка не применяется, итог пересчитывается без неё.

### 3.5. Контрольные значения (обязательно должны совпасть в тестах)

| # | Конфигурация | Итог, ₽ |
|---|---|---|
| 1 | Премиум, 12 мес, промокод 12345 | 49 470 |
| 2 | Стандарт, 3 мес, шкафчик | 11 475 |
| 3 | Базовый, 1 мес, 10 тренировок | 15 500 |
| 4 | Базовый, 1 мес, 9 тренировок | 16 000 |
| 5 | Базовый, 6 мес, полотенце, промокод 12345 | 14 841 |
| 6 | Стандарт, 12 мес | 35 700 |

## 4. Форма заявки

| Поле | Правило |
|---|---|
| Имя | обязательно; 2–50 символов; только буквы (кириллица/латиница), пробел, дефис |
| Телефон | обязательно; после удаления пробелов, скобок и дефисов должен соответствовать `^\+7\d{10}$` |
| Email | необязательно; если заполнен — корректный формат |
| Согласие на обработку данных | обязательный чекбокс |

- Ошибка показывается под полем после потери фокуса (`blur`) и при попытке отправки.
- Над кнопкой отправки выводится краткая сводка выбранного в калькуляторе абонемента (тариф, срок, итог).
- Отправка эмулируется: объект `{ форма + конфигурация + итог }` выводится в `console.log`, показывается сообщение «Заявка отправлена», форма очищается. Никаких сетевых запросов.

## 5. Технологии и архитектура

**Стек:** React 18 + TypeScript (strict) + Vite. Стили — CSS Modules или обычный CSS с БЭМ, без UI-библиотек. Тесты — Vitest + React Testing Library + jsdom. Линтер — ESLint (стандартный конфиг Vite).

**Архитектура:** бизнес-логика (расчёт и валидация) — чистые функции без React и DOM, вынесены в `src/lib`. Компоненты только отображают данные и вызывают эти функции. Тарифы и цены хранятся в одном конфиге `src/config/pricing.ts`. Состояние калькулятора поднято в `App`, чтобы форма получала выбранную конфигурацию.

```
pulsefit/
├── index.html
├── src/
│   ├── main.tsx
│   ├── App.tsx
│   ├── config/pricing.ts          # тарифы, скидки, цены услуг
│   ├── lib/
│   │   ├── calculator.ts          # calculatePrice(config): PriceBreakdown
│   │   ├── validation.ts          # validateName, validatePhone, validateEmail, validateTrainings
│   │   └── format.ts              # formatRub
│   ├── types.ts                   # Plan, MembershipConfig, PriceBreakdown, ValidationResult
│   ├── components/                # Header, Hero, About, Plans, Calculator, OrderForm, Footer
│   └── styles/
├── tests/
│   ├── calculator.test.ts
│   ├── validation.test.ts
│   └── components/                # Calculator.test.tsx, OrderForm.test.tsx
├── report/                        # шаблон, скрипт генерации отчёта, скриншоты
└── package.json                   # скрипты: dev, build, test, test:coverage, lint
```

**Нефункциональные требования:**
- Адаптивность 360–1440+ px.
- Последние версии Chrome, Firefox, Safari, Edge.
- Lighthouse Performance и Accessibility ≥ 90.
- Семантическая разметка, `label` у всех полей, видимый фокус, `aria-invalid` и `aria-describedby` для ошибок.
- Только статические файлы, без бэкенда.

## 6. Тестирование

1. **Unit-тесты, белый ящик** (`calculator.test.ts`, `validation.test.ts`): все ветки `calculatePrice` (каждый тариф и срок, применение промокода — действующий, с пробелами, недействующий, пустой; граница 9/10 тренировок, доп. услуги), все 6 контрольных значений из п. 3.5, все функции валидации.
2. **Граничные значения:** тренировки −1, 0, 20, 21, 2.5, пустая строка; имя длиной 1, 2, 50, 51; телефон с 9, 10, 11 цифрами после +7, с форматированием `+7 (999) 123-45-67`.
3. **Компонентные тесты** (RTL): калькулятор пересчитывает итог при смене тарифа; форма показывает ошибки при пустой отправке и сообщение об успехе при корректных данных.
4. **Покрытие:** `vitest --coverage`, цель ≥ 90 % для `src/lib`.
5. **Чёрный ящик (ручное):** составь таблицу из 8 тест-кейсов по требованиям (ID, шаги, ожидаемый результат, фактический результат, статус). Прогони их сам через Playwright (он предустановлен) и заполни фактический результат.
6. **Адаптивность:** скриншоты страницы через Playwright на 360, 768 и 1440 px.
7. **Lighthouse:** если запускается в окружении — сохрани результат; если нет, скажи мне, я прогоню сам и пришлю скриншот.

Для отчёта сохрани в `report/assets/`: вывод прогона тестов, отчёт покрытия (таблица), скриншоты страницы и калькулятора.
